# Tokyo Afterlife Bureau: six-slide pitch outline

Proposed content and speaker notes for a future editable deck. No PowerPoint export has been generated. The current web Demo room remains the working presentation. Use cream, navy and red; prefer native text and simple vector illustrations so the eventual source deck can be shared without private media.

## 1. The object we stopped noticing

**On screen:** “A little forgotten. A lot of soul.” A small umbrella beside a closed drawer. One sentence: “Give a forgotten object a second chance.”

**Speaker notes:** “Think of something you still own but stopped using: an umbrella, a lamp, a kettle. Tokyo Afterlife Bureau starts with that familiar object and helps you see a next chapter for it.”

**Show:** Open the bureau home screen. Introduce the product as a creative prototype, not an established waste-reduction service. Do not add unsupported market or environmental statistics.

## 2. A photo and a memory

**On screen:** Object → memory → case intake. Example input: “An umbrella I carried through my first Tokyo summer. One rib is bent.” Mark this as an illustrative demo input.

**Speaker notes:** “Take a photo, choose an object category and add a memory. The memory provides the personal detail. For a reliable judging walkthrough, we also offer authored sample cases that require no upload or AI key.”

**Show:** Open intake or choose a sample. Distinguish a real live submission from the no-upload sample path before demonstrating either.

## 3. The object finds a voice

**On screen:** A case-file reveal: fictional spirit name, personality, short story and wish. A small label reads “Original fiction inspired by object-spirit folklore.”

**Speaker notes:** “In live mode, a vision model receives the resized photo and memory and writes a fictional character. Sample mode uses authored category stories. Both paths make that distinction visible. The portrait is an illustrated archetype; personalized image generation is a future extension.”

**Show:** Reveal a case and read one short line from the displayed story. Do not imply sample text was generated live or present the invented character as an authentic traditional legend.

## 4. A story becomes a next step

**On screen:** Repair · Reuse · Pass on. A selected action becomes a saved promise.

**Speaker notes:** “The reveal is only the beginning. Each category has curated, general suggestions. Choose one next step and save a promise with the case. Electrical faults need qualified assessment; this app does not diagnose repairs.”

**Show:** Open Next chapter, choose a promise and save the case. A saved promise records intent; it does not prove repair completion or waste reduction.

## 5. What the system actually does

**On screen:** Two clearly separated paths:

- **Sample:** device input → authored category story → curated actions → device-local case.
- **Live:** resized photo + memory → private server route → OpenRouter/model provider → validated fictional character → curated actions → device-local case.

**Speaker notes:** “Keys stay on the server. Sample mode does not upload the photo. Live mode sends it to the configured AI providers, after the app identifies that behavior. Saved cases remain in this browser's local storage; they are not encrypted by the app. The current hosted demo is private.”

**Show:** The interactive explanation and mode labels. Describe local storage as device-local convenience, not secure cloud storage or cross-device synchronization.

## 6. Try the bureau; imagine the next chapter

**On screen:** “Meet a spirit. Make a promise.” Three realistic future directions: personalized portraits, verified local repair/reuse information, and optional native app packaging.

**Speaker notes:** “The mobile web prototype already demonstrates intake, a character reveal, practical actions, saved promises and an explainable sample/live boundary. Next we would test whether the story makes people more willing to act, then connect verified local services. iPhone and Android packaging would follow validation of the web experience.”

**Show:** My case files with the saved promise, then invite the audience to try a sample. Use the short film only where its private media is present and authorized; the interactive explanation must still work without it.

## Rehearsal sequence

Use one sample object throughout. Open Demo room → show the explanation → reveal the sample → select a next step → save it → show My case files. Keep a live request optional so provider latency or network failure does not interrupt the core demonstration. State when prerecorded or authored material is being shown. Timing, audience and final slide design remain open for a future deck brief.
